# `tools/`

**Emitters, and any check that is a multi-file module: one directory per tool.** An emitter writes
generated output under `artifacts/` and nothing else, is deterministic, and lands with its
`:check` twin (`CLAUDE.md` § The script suffix contract). A single-file gate lives under
`scripts/`.

Each tool's header is the authority on it: what it emits or checks, the failure it exists to
prevent, its invocation and what it needs (`CLAUDE.md` § Standing rules for prompts and gates).
Where a row here and a header disagree, the header wins and the row is corrected.

| Path | Kind | What it is, or what it refuses |
|---|---|---|
| `citations/` | gate, `citations:check`, and its selftest, `citations:selftest` | Refuses a `<file>.md:NN` or `<file>.md` § `<Heading>` pointer, in any tracked text file (a section pointer that one line break splits included), that names a file that is not tracked, a line past the end or blank, or a section that does not exist; and a pointer into a store this repository does not use. `check.ts` is the gate, `scan.ts` the scanner and its exemption lists (each entry with its reason) and the `CITATIONS_ROOT` override, `memory.ts` the unused-store rule, `selftest.ts` the fixtures that hold the scanner to known answers and run the gate end to end over a synthetic tree. Beside the gate, `support.ts` is an advisory, `citations:support`, that no job runs: it judges with TypeSafe whether the section a citation names says what the citing sentence claims, and prints the citations that fall under `citationSupportMinProbability` for a person to read. When `TYPESAFE_API_KEY` is not set it says so and falls back to an offline word-overlap check at `citationSupportOverlapMinShare`, and when a call fails it fails. `support.selftest.ts` is its selftest, `citations:support:selftest`, over a fixture tree and a stubbed judge. |
| `coupling/` | emitter, `coupling`, and its baseline's `coupling:update`; gate, `coupling:check`; selftest, `coupling:selftest` | Writes the co-change map, `artifacts/coupling/cochange.json`: which files change together in the pull requests merged to `main`, read from git history through the one trunk commit the map records, `throughCommit`, with hub files and clusters. Only `coupling:update` moves that commit, so an ordinary pull request leaves the map alone (`docs/decisions.md` § D-24). It refuses the map differing from what it re-derives, any other file under `artifacts/coupling/`, a `throughCommit` off `origin/main`'s first-parent chain, a merge commit on the chain, a shallow clone, and a `coupling*` key of `tools/policy.json` missing or malformed, and it prints how many pull requests landed after the baseline. It compares its history walk with a hand-ratified fixture before it writes or checks anything. `coupling.ts` is the emitter and the gate, `selftest.ts` its fixture repositories. `COUPLING_ROOT` points it at a doctored copy. |
| `trace/` | emitter, `trace`, and its baseline's `trace:update`; gate, `trace:check`; selftest, `trace:selftest` | Writes the traceability record, `artifacts/trace/record.json`, and that directory's `README.md`, from the specs, the tests read through `scripts/test-trace.mjs`, the contracts and the tasks each commit on HEAD names. It refuses what its header's rules refuse: either file differing from what it re-derives, any other file under `artifacts/trace/`, a commit of the branch that changes `apps/` and names no task, a contract operation with no contract test, a test with no ID or no artifact hash, and an ID nothing heads. It also refuses a hash that is not current, a scenario without its happy-path or negative test that the baseline does not list, and a baseline, `artifacts/trace/baseline.json`, that rose, lists an obligation now met, or is not as `trace:update` writes it. It compares its history walk with a hand-ratified fixture before it writes or checks anything. `trace.ts` is the emitter and the gate, `selftest.ts` its fixture repositories. `TRACE_ROOT` points it at a doctored copy. |
| `lib/paths.ts` | helper | Where the repository root is, in a module with no side effects, so a tool can ask without running anything. |
| `lib/bd-launcher.ts` | helper | Finds the tracker's CLI on this machine and starts it without a shell. Only "not found" is a skip; found and not runnable is a failure, reported with the launcher and the error. |
| `policy.json` | policy file | The workflow's constants that belong to no one tool, each under a key with a `<key>Means` sibling (`docs/decisions.md` § D-03). `specChangeLabel` is the label on a product change's epic and tasks; `openspec:check` refuses a skill or agent that spells it without citing the key, or cites it and spells another value. `specIdPrefixes` is the prefix of each capability's scenario and NFR IDs, and `openspec:check` reads it to refuse a header without its capability's ID, one ID on two headers, and an ID an archived change gave another title. `testTraceHashLength` and `testTraceLayers` are the length of the hash a test's `// trace:` line carries for each artifact it was written against, and the layers a test may declare, each with its default orchestration level; `scripts/test-trace.mjs`, the convention's home, reads them with `prReviewIssuePattern` as the shape of a task's ID, `calculator:test` refuses its run without them, and `tests:trace:selftest` refuses a policy with no hash length. `traceObligationLayers` names the layers whose tests count toward a scenario's happy-path and negative obligation; `trace:check` counts only those, and refuses a layer there that `testTraceLayers` does not list. `testInventoryTrailer` is the key of the git trailer that records an architect's decision to remove, skip or weaken a test on a branch; `tests:inventory:check` reads it from the policy at HEAD and refuses its run without it, and `tests:inventory:selftest` refuses a policy with none. `thresholdPercents` and `thresholdMinSamples` are the coverage and mutation thresholds and the samples below which no rate is given, `thresholdScope` the files counted as the product's code, and `mutationCommands` the files mutated as Commands, each with the test files its run runs; `scripts/check-thresholds.mjs` reads the four, refuses its run without them, and `thresholds:selftest` refuses a policy with none. `assetLabels`, `foundAtLabels` and `rerouteLabels` are the labels a run leaves in the tracker, so `bd count` shows what recurs across runs (`docs/decisions.md` § D-06); `beads:check` holds `assetLabels`, and no gate holds the other two yet. `foundIssueCommand` is the command that files a found issue with those labels, which `.claude/skills/bead/SKILL.md` § 4 and `.claude/skills/change-build/SKILL.md` § 5 cite and spell no part of; no gate holds it. The four `buildReview*` keys size the review `.claude/workflows/build-change-task.js` runs on each task of a product change. `buildRedFirstKinds` names the kinds of task it stops as `not-red`, before any review, when a scenario the parent named has neither a red record nor an already-green report (`docs/decisions.md` § D-14). `buildIndependentKinds`, `buildArchitectMaxRounds`, `independentInputs`, `independentTestDir`, `independentLayers` and `architectRunLayers` say for which kinds of task it runs a test-builder, what that agent may read, where its tests live, which of them the architect runs and how many times (`docs/decisions.md` § D-13, items 12, 16 and 17). The three `verifyTrace*` keys size the scenario trace `.claude/workflows/verify-change-trace.js` takes at verify; `freshRunDeadlineSeconds` is the most one call of `scripts/fresh-run.mjs` may take before its children are killed and its clone removed, and the run refuses without it; `workflows:selftest` holds all fourteen. The three `session*` keys bound a review or design workflow a session writes itself (`CLAUDE.md` § A workflow a session writes itself is bounded; `docs/decisions.md` § D-16), and no gate holds them. The `promptReview*` keys are the markers, thresholds and skeptic counts of the batched prompt review (`.claude/skills/close-prompt-run/SKILL.md`; `docs/decisions.md` § D-08, § D-10 and § D-17): `workflows:selftest` holds the three `.claude/workflows/review-prompts.js` reads, and no gate holds the markers or the due thresholds. The `promptWordBudget*` keys are the most words each prompt may hold, one key per prompt: every skill and agent, `CLAUDE.md`, `AGENTS.md`, the worktree briefing template and the string literals of each workflow. `check:prompts` refuses a prompt over its budget or with none, and `prReviewHighRiskJsonKeys` makes every change to one a person's to merge. `typesafeModel` is the model every TypeSafe question is sent to, and the eight `citationSupport*` keys are the threshold, skip list, passage and claim sizes, width, cap and offline share of `citations:support`; the command reads all nine, refuses its run without one or without its `Means` sibling, and `citations:support:selftest` holds both. The eight `coupling*` keys say how `tools/coupling/coupling.ts` reads the trunk's merged pull requests into the co-change map: the committer address of a merge, the paths it ignores, its rename similarity, the most files a counted pull request may change, and the thresholds of an edge, a rate's sample, a hub and a cluster. `coupling:check` refuses its run without one, without its `Means` sibling or of the wrong shape, and `coupling:selftest` holds each refusal. |
| `lib/typesafe.ts` | helper | The one TypeSafe client every tool here shares, behind a `TypeSafeJudge` a selftest stubs. A missing `TYPESAFE_API_KEY` is a skip with its reason; once a key is set every error the SDK throws propagates, so a failed call is never read as "no findings". No caller runs in a gate; each caller's selftest runs in both tiers over a stub. |
| `lib/git-env.ts` | helper | This process's environment without any `GIT_*` key, so git run against a scratch tree from inside a hook reads that tree and not this checkout. `citations:selftest` imports it and asserts it leaks no such key. `gitIn` runs git in one tree with that environment, `gitOk` asks a git command's exit status alone, and `SCRATCH_GIT_ENV` is the environment of a scratch repository, with no configuration of this machine's; the trace and co-change emitters share all three. |
| `lib/committed.ts` | helper | How an emitter's `:check` reads the file it committed, line endings normalised, and names the first line where it differs from what it re-derives. The trace and co-change emitters share it, so a stale file is reported in the same words by both. |
