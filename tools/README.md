# `tools/`

**Emitters, and any check that is a multi-file module: one directory per tool.** An emitter writes
generated output under `artifacts/` and nothing else, is deterministic, and lands with its
`:check` twin (`CLAUDE.md` § The script suffix contract). A single-file gate lives under
`scripts/`.

Each tool's header is the authority on it: what it emits or checks, the failure it exists to
prevent, its invocation and what it needs (`CLAUDE.md` § Standing rules for prompts and gates).
Where a row here and a header disagree, the header wins and the row is corrected.

| Path | Kind | What it is, or what it refuses |
|---|---|---|
| `citations/` | gate, `citations:check`, and its selftest, `citations:selftest` | Refuses a `<file>.md:NN` or `<file>.md` § `<Heading>` pointer, in any tracked text file, that names a file that is not tracked, a line past the end or blank, or a section that does not exist; and a pointer into a store this repository does not use. It reads a section pointer whose file name is not backticked, one that one line break splits, and each of several on one line. `check.ts` is the gate, `scan.ts` the scanner and its exemption lists (each entry with its reason) and the `CITATIONS_ROOT` override, `memory.ts` the unused-store rule, `selftest.ts` the fixtures that hold the scanner to known answers and run the gate end to end over a synthetic tree. Beside the gate, `support.ts` is an advisory, `citations:support`, that no job runs: it judges with TypeSafe whether the section a citation names says what the citing sentence claims, and prints the citations that fall under `citationSupportMinProbability` for a person to read. When `TYPESAFE_API_KEY` is not set it says so and falls back to an offline word-overlap check at `citationSupportOverlapMinShare`, and when a call fails it fails. `support.selftest.ts` is its selftest, `citations:support:selftest`, over a fixture tree and a stubbed judge. |
| `coupling/` | emitter, `coupling`, and its baseline's `coupling:update`; gate, `coupling:check`; selftest, `coupling:selftest` | Writes the co-change map, `artifacts/coupling/cochange.json`: which files change together in the pull requests merged to `main`, read from git history through the one trunk commit the map records, `throughCommit`, with hub files and clusters. Only `coupling:update` moves that commit, so an ordinary pull request leaves the map alone (`docs/decisions.md` § D-24). It refuses the map differing from what it re-derives, any other file under `artifacts/coupling/`, a `throughCommit` off `origin/main`'s first-parent chain, a merge commit on the chain, a shallow clone, and a `coupling*` key of `tools/policy/tool-settings.json` missing or malformed, and it prints how many pull requests landed after the baseline. It compares its history walk with a hand-ratified fixture before it writes or checks anything. `coupling.ts` is the emitter and the gate, `selftest.ts` its fixture repositories. `COUPLING_ROOT` points it at a doctored copy. |
| `harness/` | assessment, `harness` and `harness:graph`; selftest, `harness:selftest` | Reports, and enforces nothing, where what the harness declares disagrees with what its code does (`docs/decisions.md` § D-26). `harness.ts`, the core, reads committed files and the co-change map. It writes a dated report under `.scratch/harness/` of each hook job whose glob misses an input, by kind: a module its entry imports, a pinned package's manifest or lockfile, a file it reads from the checkout, a script it launches, a generated file its check compares. It also reports each gate a README table names that nothing runs, each script run at pre-push or in CI but not both and not declared so, and code files that change together and import neither way. Each item is a finding, a lead or a note under a stable key, compared with the last report. `graph.py`, the graph half, standard-library Python run by the `python` that `mise.toml` pins, reads that report beside the local code graph and the map. It reports the graph's freshness and the co-change pairs the graph has no edge for, and writes one combined graph, recording the graph it was built from. Run from the checkout that holds the graph, it writes it beside the graph, where `scripts/code-graph.mjs` serves it while that is the graph beside it (`docs/decisions.md` § D-28); from a worktree, whose wiring is its branch's, or with `--graph`, beside its report, not served. It refuses to write that graph with `multigraph` false, which loses edges in graphify's loader, or with a co-change pair written one way, which `graphify affected` cannot see from one end. `harness.config.json` holds every repository-specific fact both read, each with its `Means`. `selftest.ts` plants one gap per case in fixture repositories, then runs the graph half's own selftest. `HARNESS_ROOT` points both at a doctored copy. |
| `trace/` | emitter, `trace`, and its baseline's `trace:update`; gate, `trace:check`; selftest, `trace:selftest` | Writes the traceability record, `artifacts/trace/record.json`, and that directory's `README.md`, from the specs, the tests read through `scripts/test-trace.mjs`, the contracts and the tasks each commit on HEAD names. It refuses what its header's rules refuse: either file differing from what it re-derives, any other file under `artifacts/trace/`, a commit of the branch that changes `apps/` and names no task, a contract operation with no contract test, a test with no ID or no artifact hash, and an ID nothing heads. It also refuses a hash that is not current, a scenario without its happy-path or negative test that the baseline does not list, and a baseline, `artifacts/trace/baseline.json`, that rose, lists an obligation now met, or is not as `trace:update` writes it. It compares its history walk with a hand-ratified fixture before it writes or checks anything. `trace.ts` is the emitter and the gate, `selftest.ts` its fixture repositories. `TRACE_ROOT` points it at a doctored copy. |
| `lib/paths.ts` | helper | Where the repository root is, in a module with no side effects, so a tool can ask without running anything. |
| `lib/bd-launcher.ts` | helper | Finds the tracker's CLI on this machine and starts it without a shell. Only "not found" is a skip; found and not runnable is a failure, reported with the launcher and the error. |
| `policy/` | policy records | The workflow's policy: every constant a prompt or a tool reads, under a key with its reason beside it, in five records split by who may change each key and who reads it (`docs/decisions.md` § D-27). `vocabulary.json` holds the spellings every stage agrees on, `agent-workflows.json` the sizes and bounds of the agent workflows, `pr-review.json` what the pull-request reviewer decides by, `prompt-budgets.json` each prompt's word budget, and `tool-settings.json` the settings of single tools; a person merges every change to `pr-review.json` and `prompt-budgets.json`. `tools/policy/README.md` has a row per record, and each record's `gatedBy` names the gates that hold its values. `check:policy` refuses a record without its header, a constant without its `Means`, a key in two records, and a record that README does not name. |
| `lib/typesafe.ts` | helper | The one TypeSafe client every tool here shares, behind a `TypeSafeJudge` a selftest stubs: `choose` asks one Choice, and `noul` asks several yes/no questions over one state in one request. Every call runs in a script a session or a person runs, never in a gate or a workflow (`docs/decisions.md` § D-42). A missing `TYPESAFE_API_KEY` is a skip with its reason; once a key is set every error the SDK throws propagates, so a failed call is never read as "no findings". No caller runs in a gate; each caller's selftest runs in both tiers over a stub. |
| `lib/git-env.ts` | helper | This process's environment without any `GIT_*` key, so git run against a scratch tree from inside a hook reads that tree and not this checkout. `citations:selftest` imports it and asserts it leaks no such key. `gitIn` runs git in one tree with that environment, `gitOk` asks a git command's exit status alone, and `SCRATCH_GIT_ENV` is the environment of a scratch repository, with no configuration of this machine's; the trace and co-change emitters share all three. |
| `lib/committed.ts` | helper | How an emitter's `:check` reads the file it committed, line endings normalised, and names the first line where it differs from what it re-derives. The trace and co-change emitters share it, so a stale file is reported in the same words by both. |
| `lib/policy.ts` | helper | Reads the policy whole: every record under `tools/policy/` merged into one object, the records' headers left out, refusing a key two records define. Every gate, tool and workflow that reads a constant reads it here, so a key can move between records without its readers changing; `node tools/lib/policy.ts <key>...` prints keys for a prompt or a workflow's command, and fixtures copy and doctor the records through it. |
