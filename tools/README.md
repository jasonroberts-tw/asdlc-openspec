# `tools/`

**Emitters, and any check that is a multi-file module: one directory per tool.** An emitter writes
generated output under `artifacts/` and nothing else, is deterministic, and lands with its
`:check` twin (`CLAUDE.md` § The script suffix contract). A single-file gate lives under
`scripts/`.

Each tool's header is the authority on it: what it emits or checks, the failure it exists to
prevent, its invocation and what it needs (`CLAUDE.md` § Standing rules for prompts and gates).
Where a row here and a header disagree, the header wins and the row is corrected.

| `citations/` | gate, `citations:check`, and its selftest, `citations:selftest` | Refuses a `<file>.md:NN` or `<file>.md` § `<Heading>` pointer, in any tracked text file (a section pointer that one line break splits included), that names a file that is not tracked, a line past the end or blank, or a section that does not exist; and a pointer into a store this repository does not use. `check.ts` is the gate, `scan.ts` the scanner and its exemption lists (each entry with its reason) and the `CITATIONS_ROOT` override, `memory.ts` the unused-store rule, `selftest.ts` the fixtures that hold the scanner to known answers and run the gate end to end over a synthetic tree. |
| `trace/` | emitter, `trace`, and its baseline's `trace:update`; gate, `trace:check`; selftest, `trace:selftest` | Writes the traceability record, `artifacts/trace/record.json`, and that directory's `README.md`, from the specs, the tests read through `scripts/test-trace.mjs`, the contracts and the tasks each commit on HEAD names, and refuses what its header's rules refuse: either file differing from what it re-derives, any other file under `artifacts/trace/`, a commit of the branch that changes `apps/` and names no task, a contract operation with no contract test, a test with no ID or no artifact hash, an ID nothing heads, a hash that is not current, a scenario without its happy-path or negative test that the baseline does not list, and a baseline, `artifacts/trace/baseline.json`, that rose, lists an obligation now met, or is not as `trace:update` writes it. | `lib/paths.ts` | helper | Where the repository root is, in a module with no side effects, so a tool can ask without running anything. |
| `lib/bd-launcher.ts` | helper | Finds the tracker's CLI on this machine and starts it without a shell. Only "not found" is a skip; found and not runnable is a failure, reported with the launcher and the error. |
| `policy.json` | policy file | The workflow's constants that belong to no one tool, each under a key with a `<key>Means` sibling (`docs/decisions.md` § D-03). `specChangeLabel` is the label on a product change's epic and tasks; `openspec:check` refuses a skill or agent that spells it without citing the key, or cites it and spells another value. `specIdPrefixes` is the prefix of each capability's scenario and NFR IDs, and `openspec:check` reads it to refuse a header without its capability's ID, one ID on two headers, and an ID an archived change gave another title. `testTraceHashLength` and `testTraceLayers` are the length of the hash a test's `// trace:` line carries for each artifact it was written against, and the layers a test may declare, each with its default orchestration level; `scripts/test-trace.mjs`, the convention's home, reads them with `prReviewIssuePattern` as the shape of a task's ID, `calculator:test` refuses its run without them, and `tests:trace:selftest` refuses a policy with no hash length. `traceObligationLayers` names the layers whose tests count toward a scenario's happy-path and negative obligation; `trace:check` counts only those, and refuses a layer there that `testTraceLayers` does not list. `testInventoryTrailer` is the key of the git trailer that records an architect's decision to remove, skip or weaken a test on a branch; `tests:inventory:check` reads it from the policy at HEAD and refuses its run without it, and `tests:inventory:selftest` refuses a policy with none. `thresholdPercents` and `thresholdMinSamples` are the coverage and mutation thresholds and the samples below which no rate is given, `thresholdScope` the files counted as the product's code, and `mutationCommands` the files mutated as Commands, each with the test files its run runs; `scripts/check-thresholds.mjs` reads the four, refuses its run without them, and `thresholds:selftest` refuses a policy with none. `assetLabels`, `foundAtLabels` and `rerouteLabels` are the labels a run leaves in the tracker, so `bd count` shows what recurs across runs (`docs/decisions.md` § D-06); `beads:check` holds `assetLabels`, and no gate holds the other two yet. The four `buildReview*` keys size the review `.claude/workflows/build-change-task.js` runs on each task of a product change, `buildRedFirstKinds` names the kinds of task it stops as `not-red`, before any review, when a scenario the parent named has neither a red record nor an already-green report (`docs/decisions.md` § D-14), `buildIndependentKinds`, `buildArchitectMaxRounds`, `independentInputs`, `independentTestDir`, `independentLayers` and `architectRunLayers` say for which kinds of task it runs a test-builder, what that agent may read, where its tests live, which of them the architect runs and how many times (`docs/decisions.md` § D-13, items 12, 16 and 17), and the three `verifyTrace*` keys size the scenario trace `.claude/workflows/verify-change-trace.js` takes at verify; `freshRunDeadlineSeconds` is the most one call of `scripts/fresh-run.mjs` may take before its children are killed and its clone removed, and the run refuses without it; `workflows:selftest` holds all fourteen. The three `session*` keys bound a review or design workflow a session writes itself (`CLAUDE.md` § A workflow a session writes itself is bounded; `docs/decisions.md` § D-16), and no gate holds them. The `promptReview*` keys are the markers, thresholds and skeptic counts of the batched prompt review (`.claude/skills/close-prompt-run/SKILL.md`; `docs/decisions.md` § D-08, § D-10 and § D-17): `workflows:selftest` holds the three `.claude/workflows/review-prompts.js` reads, and no gate holds the markers or the due thresholds. The `promptWordBudget*` keys are the most words each prompt may hold, one key per prompt: every skill and agent, `CLAUDE.md`, `AGENTS.md`, the worktree briefing template and the string literals of each workflow. `check:prompts` refuses a prompt over its budget or with none, and `prReviewHighRiskJsonKeys` makes every change to one a person's to merge. |
