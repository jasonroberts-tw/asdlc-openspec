# `scripts/`

**Single-file gates and git-job scripts: each one either refuses something or does one job a hook
or an operator calls.** An emitter, or a check that is a multi-file module, lives under
`tools/`; a Claude Code hook lives under `scripts/hooks/`.

Each file's header is the authority on it: what it checks, the failure it exists to prevent, its
invocation and what it needs (`CLAUDE.md` § Standing rules for prompts and gates). Where a row here
and a header disagree, the header wins and the row is corrected.

| File | Kind | What it is, or what it refuses |
|---|---|---|
| `assert-not-hand-edited.mjs` | pre-commit job | Refuses a staged file that a generator owns and that no longer matches what the generator produces, and names where the change belongs. One verifier per generator, chosen by path; a suspect nothing can verify is reported, never waved through. |
| `check-beads.mjs` | gate, `beads:check`; selftest, `beads:selftest` | Refuses an open issue that does not name where its work lands, an open issue filed `discovered-from` another that carries no label `assetLabels` in `tools/policy/vocabulary.json` lists, and an issue citing an identifier that does not resolve from this checkout. The gate is pre-push only: it reads the tracker's database. It skips clean only when `bd` is not found; a `bd` that is found and fails is a failure. `BEADS_CHECK_ROOT` points it at a doctored copy holding a policy and an export, and runs no `bd`; the selftest reads its fixtures that way, so it is a CI step as well. |
| `check-count-index.mjs` | gate, `counts:check` | Refuses a value in `count-index.md` that differs from what its source gives, a key with no source, and a deriver whose key is gone. The table is updated from what it reports, never the reverse. |
| `check-jobs.mjs` | gate, `check:jobs`; selftest, `check:jobs:selftest` | Refuses a job in `git-hooks.yml` or `.github/workflows/verify.yml` that names a package script that does not exist; a package script no job runs that its own table does not declare by kind; an entry in that table that names no script, names one twice, names one a job runs, or is shaped unlike its kind; a `tools/`, `scripts/` or `apps/` path a script names that does not exist as spelled, case included; and a glob a script names that matches no file, expanded by `fs.globSync` as the test runner expands it. `CHECK_JOBS_ROOT` points it at a doctored copy. |
| `check-openspec.mjs` | gate, `openspec:check` | Refuses a living spec or active change under `openspec/` that the pinned OpenSpec CLI does not validate strictly, an active change whose deltas do not apply to the living spec (trial-archived in a scratch copy), a living spec still carrying the archive's placeholder Purpose, a scenario or NFR requirement without its capability's ID (the prefix read from `specIdPrefixes` in `tools/policy/vocabulary.json`), one ID on two headers, and an ID an archived delta gave another title, a retired `openspec-*` skill written back under `.claude/skills/`, and a skill or agent that spells the change label without citing `specChangeLabel` in `tools/policy/vocabulary.json`, or cites it and spells another value. |
| `check-policy.mjs` | gate, `check:policy`; selftest, `check:policy:selftest` | Refuses a record under `tools/policy/` that does not parse as a JSON object, lacks one of the five header fields `tools/lib/policy.ts` names, or holds no constant. Refuses a constant with no `Means` sibling, a `Means` with no constant, and a key two records define. Refuses a record `tools/policy/README.md` does not name, a row there that names no record, any other file in the directory, and `tools/policy.json` back beside the records, where a key would reach no reader (`docs/decisions.md` § D-27). What each value must be is held by the gates its record's `gatedBy` names. `POLICY_CHECK_ROOT` points it at a doctored copy. |
| `check-prompts.mjs` | gate, `check:prompts` | Refuses a skill under `.claude/skills/` or an agent under `.claude/agents/` whose first line after its frontmatter is not the sentence `CLAUDE.md` § Standing rules for prompts and gates requires, and a `CLAUDE.md` that no longer states it. Refuses a prompt over its word budget in `tools/policy/prompt-budgets.json`, a prompt with no row there, a row with no reason or whose budget is not a whole number, and a row that names no prompt. The prompts are every skill and agent, `CLAUDE.md`, `AGENTS.md`, `.claude/worktree-CONTEXT.md.tmpl` and each workflow under `.claude/workflows/`, which is counted on its string literals alone. `--counts` prints each prompt's words and budget. `PROMPTS_CHECK_ROOT` points it at a doctored copy. |
| `check-reference-mirrors.mjs` | gate | Refuses an imported file under `reference/` whose hash or byte count disagrees with its manifest row, a manifest row with no file, and an import that ships without its manifest or its README. |
| `check-thresholds.mjs` | gate, `thresholds:check` and `thresholds:commands:check`; emitter of its baseline, `thresholds:update`; selftest, `thresholds:selftest` | Refuses changed code under `apps/`, against the merge base with `origin/main`, whose code lines or branches Node's own coverage finds run below `thresholdPercents` in `tools/policy/tool-settings.json`, or whose Routines' or Commands' mutants StrykerJS finds detected below it; below a minimum sample in `thresholdMinSamples`, it gives the counts and no rate and refuses any one gap no directive excuses with a reason. It mutates changed lines only, so a change to a test alone mutates nothing. It refuses too a `node:coverage` or `Stryker disable` directive with no reason or over more than one line, a failing suite, and an entry of the ratchet baseline, `artifacts/thresholds/baseline.json`, that is not one the merge base lists carried through the branch's edits, so the baseline may fall and never rise. It runs the tests through `run-tests.mjs`. `THRESHOLDS_ROOT` points it at a doctored copy. |
| `check-register-status.mjs` | gate, `check:register` | Refuses a register whose header range, summary table or dates disagree with the entries below them. |
| `check-test-inventory.mjs` | gate, `tests:inventory:check`; selftest, `tests:inventory:selftest` | The home of the rule that no test is removed, skipped or weakened without a recorded architect decision. It compares the tests at HEAD with those at its merge base with `origin/main`, both read from git through `test-trace.mjs`, and refuses a test removed, one given a skip, a todo or an only, and one with fewer assertion call sites, unless a commit on the branch carries the trailer `testInventoryTrailer` in `tools/policy/vocabulary.json` spells, naming the test and the reason, its key spelled exactly. A test renamed with its call unchanged and every ID of its old name kept is not a removal; a skip counts on the test, its suite, a `before` or `beforeEach` hook, and the top-level constant a skip option names. It fails, rather than passes, in a shallow clone, one with no `origin/main`, on a test call it cannot read to its end, and on a `describe` or `suite` used other than as a call of its own name. `TEST_INVENTORY_ROOT` points it at a doctored repository. |
| `code-graph.mjs` | operator command, `code-graph` and `code-graph:mcp`; selftest, `code-graph:selftest` | Builds the local code graph with graphify into the primary checkout's gitignored `graphify-out/`, from whichever checkout runs it, and registers graphify's MCP server for it at Claude Code's local scope (`docs/decisions.md` § D-20), or for the harness assessment's combined graph beside it while that records the blob id of the `graph.json` beside it (`docs/decisions.md` § D-28). It builds with `graphify extract`, never `update`, from an empty directory outside the repository with Claude Code's safe mode and no exported API key, and stamps every item a language model produced as semantic whenever the graph changed. It refuses a graphify other than `graphifyVersion` in `tools/policy/tool-settings.json`, an MCP server that does not answer with its tools, graphify's own git hooks, saved answers under `graphify-out/memory/`, a second build at once, and a partial extraction, which graphify can write with exit 0. Not an emitter or a gate: what it writes is never committed, and it reads the network, a language model and the person's own plan. `CODE_GRAPH_ROOT` points it at another checkout, and its selftest runs it so against a fixture repository with stub tools, which is the job and the CI step. |
| `fresh-run.mjs` | operator command, `tests:fresh`, run at `change-verify` § 4; selftest, `tests:fresh:selftest` | The verifier's fresh run: it clones the change worktree's HEAD under the temporary directory, with the worktree's `origin/main` and no remote, installs it with `npm ci`, runs every test script, the trace gate and `thresholds:commands:check` there, sorts each test by the traceability record, the epic's children passed as `--tasks`, and writes `.scratch/<change>-verify.json`; `--rerun` runs one failing test once more, by name, in a fresh clone of the same commit. It refuses a tree with uncommitted changes, a checkout with no `origin/main`, a temporary root inside a repository, a failed install, and a re-run of a test that did not fail, was run again already, or is of another commit than HEAD; a result the record does not list is a problem of the run. It reads the network through `npm ci`, so its selftest over a fixture repository, the install stubbed, is the job and the step (`docs/decisions.md` § D-15, item 3). `FRESH_RUN_ROOT` and `FRESH_RUN_TMP` point it at a doctored checkout and temporary root. |
| `git-hooks.mjs` | the git hook runner, which each `hook.asdlc-<event>` entry runs; `gates`; operator command, `hooks:install`, and npm's `prepare`; selftest, `hooks:selftest` | Runs an event's jobs from `git-hooks.yml`: at pre-commit those whose globs match a staged file, at pre-push those whose globs match a pushed file, read from Git's standard input, and every job with no glob. It prints one line per job, the jobs it skipped by name and a total, and of a failing job the last `gitHooksFailedOutputBytes` of its output with the path of a file holding all of it. It refuses a key, a token or an event of `git-hooks.yml` it does not read, a policy without the cap, and a Git older than 2.54.0; at prepare-commit-msg, post-checkout and post-merge, which gate nothing, it says why it cannot start and exits 0. `--install` writes the five `hook.asdlc-*` entries into the repository's config and removes lefthook's shims; `--gates` runs pre-push through `git hook run`, forced, and refuses a checkout with no hooks installed. `GIT_HOOKS_FORCE=1` runs every job, `GIT_HOOKS_SKIP=1` none, and `GIT_HOOKS_ROOT` points it at a doctored copy. |
| `lint-ratchet.mjs` | gate, not wired until you choose a linter | Warning counts in existing code may fall and never rise, against a committed baseline; an error is refused at any count. |
| `new-worktree.sh` | operator command | The one way a worktree is provisioned: `agent/<name>` cut from `origin/main`, a checked pair of ports, and a briefing rendered by the new worktree's own renderer, so it is the base's template and never the primary checkout's. It copies in each entry of the primary checkout's Vale styles, under the StylesPath `.vale.ini` names, that the worktree lacks: the synced styles, which git ignores, and never `Layout`, which the base tracks. With none copied, it warns that Vale checks no prose in the worktree and that `vale sync` needs the network. Run from the primary checkout. |
| `pr-review.mjs` | the reviewer's decisions, run by `.github/workflows/pr-review.yml`; gate, `pr-review:check`; selftest, `pr-review:selftest` | Chooses the one pull request a reviewer run takes, writes Claude Code's brief, and turns its verdict into a status, a label and a merge. The brief carries the tracker state of each other issue the cited issues and the body name, the branch's commits with their changed lines, and, when a prompt or the policy changed, the prompts' counts over the head's files; `brief --local` writes the same for a branch before its pull request opens, for the `branch-reviewer` agent. It refuses a merge whose head moved, whose `verify` or `main`'s is not green, whose risk is high without a person's later approval, or whose verdict came from anywhere but the workflow's own comment. As a gate, it refuses a policy, workflow or agent that disagrees with the others, and a review job whose install of `bd` can exit 0 with no binary. `PR_REVIEW_ROOT` points the gate at a doctored copy. |
| `prune-worktree-branches.mjs` | operator command, `worktree:gc` | Removes registered checkouts nobody is using and deletes an agent branch only when its content is already in the trunk: an ancestor of it, the head of a pull request GitHub records as merged into it (read through `gh` when it answers), or patches already upstream, with or without their context lines. It refuses everything else, and `--dry-run` prints what it would do. |
| `python.mjs` | launcher | Runs a Python script with whichever Python 3 this machine has, probed in a per-platform order, and passes the exit code through. Fails when no interpreter is found. |
| `render-pr-body.mjs` | operator command, named at `change-verify` § 6, run when a change's pull-request body is written | Writes a change's pull-request body with its `## Scenario trace` section, the trace condensed to one row per scenario, from the result `.claude/workflows/verify-change-trace.js` returned, between a head and a tail the session wrote. It refuses to write when the rows are not one to each `#### Scenario:` of the change's delta specs, active or archived, when the trace has a gap no majority of its skeptics refuted, when a row's proof is missing, does not exercise its scenario or did not pass, or when a design lens was not read or kept. After it comes the `## Verification report` section, from the fresh run, and it refuses too a run of another change or another commit than the trace's, and a report whose verdict is not `accept`. Not an emitter or a gate: it writes only under `.scratch/`, from a result no commit holds. `workflows:selftest` holds it. |
| `render-verify-report.mjs` | operator command, run at `change-verify` § 4 | Writes a change's verification report, `.scratch/<change>-verify.md`, on either verdict, from the JSON `fresh-run.mjs` wrote, through `lib/verify-report.mjs`; the report goes on the epic as a note and is never committed. It refuses JSON that is not a fresh run's, and one for another change. Not an emitter or a gate, for the reason `render-trace.mjs` gives. `workflows:selftest` holds it. |
| `render-trace.mjs` | operator command, run at `change-verify` § 4 | Writes a change's scenario trace, `.scratch/<change>-trace.md`, from the result `.claude/workflows/verify-change-trace.js` returned: its first line naming the commit, one row per scenario of the delta specs in their order, the design decisions checked, every gap with its skeptics' votes, and every finding below a gap. It refuses a result whose rows are not one to each scenario, or a run that refused. Not an emitter or a gate, for the same reason. `workflows:selftest` holds it. |
| `render-worktree-context.mjs` | helper | Probes and allocates a worktree's ports into `.worktree/ports.env`, and renders its briefing from `.claude/worktree-CONTEXT.md.tmpl`. It is the one reader of `ports.env`, which it reads in every sibling worktree to keep their ports apart; the calculator server is given `PORT` instead. It reads the template beside itself, so `new-worktree.sh` runs the new worktree's copy. |
| `run-tests.mjs` | test runner, `calculator:test`, `calculator:test:independent` and `calculator:test:verify`; selftest, `tests:selftest` | Runs Node's own test runner over the files its quoted patterns match, and over every test file under a `--dir`, and prints its usual report, and fails the run on a failing test, a pattern that matches no file, a `--dir` that is not a directory, or a matched file that declares no test, which Node's runner reports as one passing test; a `--dir` that holds no test yet passes and says so. It reads each matched file through `test-trace.mjs` and fails the run on metadata that reader refuses, and on a test that reader and the runner do not both see, keyed by its line and name: one made in a loop, by a helper or inside another test's body, or one under a condition. Imported by `check-thresholds.mjs`, it runs once with Node's own coverage and returns the runner's summary. `--name` runs the one test of an exact name, escaped and anchored, and refuses unless exactly one test of that name ran, which is how the verifier runs a failing test once more; `--results` writes each test's file, name, status and duration as JSON, which `fresh-run.mjs` reads. `RUN_TESTS_ROOT` points it at a doctored copy. |
| `test-trace.mjs` | reader, used by `run-tests.mjs`; operator command, `cite`; selftest, `tests:trace:selftest` | The home of the convention every test's name and `// trace:` line follow: the IDs it proves, its role for each scenario, its layer and orchestration level, and a hash of each artifact it was written against. It reads a test file's source into its tests and the problems of their metadata, and hashes a scenario, an NFR requirement, a Binding Surface or a contract as its header defines; `cite <ref>` prints a ref with its current hash, to paste, and refuses a ref no trace line carries. It refuses no ID that is unknown and no hash that is stale, which `trace:check` refuses (`tools/trace/`), reading tests and specs through it. `TEST_TRACE_ROOT` points `cite` at a doctored copy. |
| `vale.selftest.mjs` | selftest, `vale:selftest` | Runs this repository's own Vale style, `.vale-styles/Layout/`, over fixtures under the temporary directory: an undoctored control that holds every construct its rules must pass and draws no alert, and one doctored case per fault, each of which must draw exactly its rule's alert at its line. It refuses too a section of `.vale.ini` that lints with a style and does not apply `Layout`. It runs `vale`, and skips clean, saying why, where none is on PATH; a `vale` that is found and fails is a failure, which it holds by running itself with a failing stub. `VALE_SELFTEST_ROOT` points it at a doctored copy. |
| `workflows.selftest.mjs` | selftest, `workflows:selftest` | Runs each workflow under `.claude/workflows/` against stubbed agents: `build-change-task.js` with the review sizes, red-first kinds and independent-test keys in `tools/policy/agent-workflows.json`, each stop and each triage route of its test-builder and architect asserted by its reason, with planted test source, assertion text and stack frames that must reach no builder or fixer, `review-prompts.js` with groups of findings it builds and the policy's `promptReview*` keys, and `verify-change-trace.js` with a change it builds and the policy's `verifyTrace*` keys, whose result it then renders with `render-trace.mjs` and `render-pr-body.mjs`, and a stubbed fresh run it renders with `render-verify-report.mjs` and `render-pr-body.mjs` alike. It refuses a workflow that stops, confirms, merges, holds or reports other than its header says, a prompt review that passes a finding below the threshold, merges an edit or a consolidation a majority of its skeptics did not uphold, or accepts a consolidation that does not say where each removed rule went, a trace that counts a group its tracer returned short or read at another commit, counts a gap nobody could verify as refuted, lets a skeptic's vote clear a proof that failed, or keeps a design reading a lens never gave, a renderer that writes with a scenario missing, a gap open or a row that did not pass, one that the Workflow runtime would not accept (a `meta` that is not a pure literal first, a phase `meta` does not declare, or a clock or random read), a workflow file it has no suite for, and a `.claude/agents/test-builder.md` whose tools are more than its structured output. `WORKFLOWS_ROOT` points it at a doctored copy. |
| `lib/trace.mjs` | helper | The scenario trace's one reading, shared by `render-trace.mjs` and `render-pr-body.mjs`: the workflow's result, the scenarios of a change's delta specs, the one-to-one match each refuses to write without, and the Markdown each writes. |
| `lib/verify-report.mjs` | helper | The verification report's one reading, shared by `render-verify-report.mjs` and `render-pr-body.mjs`: from the fresh run, the status of every Scenario, NFR, task and contract-element ID, the gap analysis in the strategy's five categories with its advisory items, the tests and runtime by layer per component, the thresholds as their gate printed them, and the verdict with every reason for it. Its figures are counts; it computes no rate. |
| `lib/test-dirs.mjs` | helper | The one home of which files `run-tests.mjs --dir <dir>` runs, every `*.test.js` at any depth under `<dir>`, and the reading of a package script's `--dir` directories. `run-tests.mjs` expands a `--dir` with it, and the trace, test-inventory and thresholds gates read a script's `--dir` through it, so a test under such a directory, the test-builder's, counts toward an obligation, is seen when removed and adds its coverage. A `--dir` with no directory throws, and each gate refuses it. |
| `lib/bin-path.mjs` | helper | Resolves a `node_modules/.bin` executable by walking up, as the package manager does, so a gate that spawns a tool runs in a linked worktree. Never `npx`: a gate fails on a missing tool, it does not download one. |
