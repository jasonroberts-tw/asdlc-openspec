# `scripts/`

**Single-file gates and git-job scripts: each one either refuses something or does one job a hook
or an operator calls.** An emitter, or a check that is a multi-file module, lives under
`tools/`; a Claude Code hook lives under `scripts/hooks/`.

Each file's header is the authority on it: what it checks, the failure it exists to prevent, its
invocation and what it needs (`CLAUDE.md` § Standing rules for prompts and gates). Where a row here
and a header disagree, the header wins and the row is corrected.

| File | Kind | What it is, or what it refuses |
|---|---|---|
| `assert-not-hand-edited.mjs` | pre-commit job | Refuses a staged file that a generator owns and that no longer matches what the generator produces, and names where the change belongs. One verifier per generator, chosen by path; a suspect nothing can verify is reported, never waved through. |
| `check-beads.mjs` | gate, `beads:check`; selftest, `beads:selftest` | Refuses an open issue that does not name where its work lands, an open issue filed `discovered-from` another that carries no label `assetLabels` in `tools/policy.json` lists, and an issue citing an identifier that does not resolve from this checkout. The gate is pre-push only: it reads the tracker's database. It skips clean only when `bd` is not found; a `bd` that is found and fails is a failure. `BEADS_CHECK_ROOT` points it at a doctored copy holding a policy and an export, and runs no `bd`; the selftest reads its fixtures that way, so it is a CI step as well. |
| `check-count-index.mjs` | gate, `counts:check` | Refuses a value in `count-index.md` that differs from what its source gives, a key with no source, and a deriver whose key is gone. The table is updated from what it reports, never the reverse. |
| `check-jobs.mjs` | gate, `check:jobs`; selftest, `check:jobs:selftest` | Refuses a job in `lefthook.yml` or `.github/workflows/verify.yml` that names a package script that does not exist; a package script no job runs that its own table does not declare by kind; an entry in that table that names no script, names one twice, names one a job runs, or is shaped unlike its kind; a `tools/`, `scripts/` or `apps/` path a script names that does not exist as spelled, case included; and a glob a script names that matches no file, expanded by `fs.globSync` as the test runner expands it. `CHECK_JOBS_ROOT` points it at a doctored copy. |
| `check-openspec.mjs` | gate, `openspec:check` | Refuses a living spec or active change under `openspec/` that the pinned OpenSpec CLI does not validate strictly, an active change whose deltas do not apply to the living spec (trial-archived in a scratch copy), a living spec still carrying the archive's placeholder Purpose, a scenario or NFR requirement without its capability's ID (the prefix read from `specIdPrefixes` in `tools/policy.json`), one ID on two headers, and an ID an archived delta gave another title, a retired `openspec-*` skill written back under `.claude/skills/`, and a skill or agent that spells the change label without citing `specChangeLabel` in `tools/policy.json`, or cites it and spells another value. |
| `check-prompts.mjs` | gate, `check:prompts` | Refuses a skill under `.claude/skills/` or an agent under `.claude/agents/` whose first line after its frontmatter is not the sentence `CLAUDE.md` § Standing rules for prompts and gates requires, and a `CLAUDE.md` that no longer states it. Refuses a prompt over its word budget in `tools/policy.json`, a prompt with no budget, a budget with no `Means` sibling or that is not a whole number, and a `promptWordBudget*` key that names no prompt. The prompts are every skill and agent, `CLAUDE.md`, `AGENTS.md`, `.claude/worktree-CONTEXT.md.tmpl` and each workflow under `.claude/workflows/`, which is counted on its string literals alone. `--counts` prints each prompt's words, key and budget. `PROMPTS_CHECK_ROOT` points it at a doctored copy. |
| `check-reference-mirrors.mjs` | gate | Refuses an imported file under `reference/` whose hash or byte count disagrees with its manifest row, a manifest row with no file, and an import that ships without its manifest or its README. |
| `check-thresholds.mjs` | gate, `thresholds:check` and `thresholds:commands:check`; emitter of its baseline, `thresholds:update`; selftest, `thresholds:selftest` | Refuses changed code under `apps/`, against the merge base with `origin/main`, whose code lines or branches Node's own coverage finds run below `thresholdPercents` in `tools/policy.json`, or whose Routines' or Commands' mutants StrykerJS finds detected below it; below a minimum sample in `thresholdMinSamples`, it gives the counts and no rate and refuses any one gap no directive excuses with a reason. It mutates changed lines only, so a change to a test alone mutates nothing. It refuses too a `node:coverage` or `Stryker disable` directive with no reason or over more than one line, a failing suite, and an entry of the ratchet baseline, `artifacts/thresholds/baseline.json`, that is not one the merge base lists carried through the branch's edits, so the baseline may fall and never rise. It runs the tests through `run-tests.mjs`. `THRESHOLDS_ROOT` points it at a doctored copy. |
| `check-register-status.mjs` | gate, `check:register` | Refuses a register whose header range, summary table or dates disagree with the entries below them. |
| `check-test-inventory.mjs` | gate, `tests:inventory:check`; selftest, `tests:inventory:selftest` | The home of the rule that no test is removed, skipped or weakened without a recorded architect decision. It compares the tests at HEAD with those at its merge base with `origin/main`, both read from git through `test-trace.mjs`, and refuses a test removed, one given a skip, a todo or an only, and one with fewer assertion call sites, unless a commit on the branch carries the trailer `testInventoryTrailer` in `tools/policy.json` spells, naming the test and the reason, its key spelled exactly. A test renamed with its call unchanged and every ID of its old name kept is not a removal; a skip counts on the test, its suite, a `before` or `beforeEach` hook, and the top-level constant a skip option names. It fails, rather than passes, in a shallow clone, one with no `origin/main`, on a test call it cannot read to its end, and on a `describe` or `suite` used other than as a call of its own name. `TEST_INVENTORY_ROOT` points it at a doctored repository. |
| `lint-ratchet.mjs` | gate, not wired until you choose a linter | Warning counts in existing code may fall and never rise, against a committed baseline; an error is refused at any count. |
| `new-worktree.sh` | operator command | The one way a worktree is provisioned: `agent/<name>` cut from `origin/main`, a checked pair of ports, and a briefing rendered by the new worktree's own renderer, so it is the base's template and never the primary checkout's. Run from the primary checkout. |
| `pr-review.mjs` | the reviewer's decisions, run by `.github/workflows/pr-review.yml`; gate, `pr-review:check`; selftest, `pr-review:selftest` | Chooses the one pull request a reviewer run takes, writes Claude Code's brief, and turns its verdict into a status, a label and a merge. It refuses a merge whose head moved, whose `verify` or `main`'s is not green, whose risk is high without a person's later approval, or whose verdict came from anywhere but the workflow's own comment. As a gate, it refuses a policy, workflow or agent that disagrees with the others, and a review job whose install of `bd` can exit 0 with no binary. `PR_REVIEW_ROOT` points the gate at a doctored copy. |
| `prune-worktree-branches.mjs` | operator command, `worktree:gc` | Removes registered checkouts nobody is using and deletes an agent branch only when its content is already in the trunk. It refuses everything else, and `--dry-run` prints what it would do. |
| `python.mjs` | launcher | Runs a Python script with whichever Python 3 this machine has, probed in a per-platform order, and passes the exit code through. Fails when no interpreter is found. |
| `render-pr-body.mjs` | operator command, named at `change-verify` § 6, run when a change's pull-request body is written | Writes a change's pull-request body with its `## Scenario trace` section, the trace condensed to one row per scenario, from the result `.claude/workflows/verify-change-trace.js` returned, between a head and a tail the session wrote. It refuses to write when the rows are not one to each `#### Scenario:` of the change's delta specs, active or archived, when the trace has a gap no majority of its skeptics refuted, when a row's proof is missing, does not exercise its scenario or did not pass, or when a design lens was not read or kept. Not an emitter or a gate: it writes only under `.scratch/`, from a result no commit holds. `workflows:selftest` holds it. |
| `render-trace.mjs` | operator command, run at `change-verify` § 4 | Writes a change's scenario trace, `.scratch/<change>-trace.md`, from the result `.claude/workflows/verify-change-trace.js` returned: its first line naming the commit, one row per scenario of the delta specs in their order, the design decisions checked, every gap with its skeptics' votes, and every finding below a gap. It refuses a result whose rows are not one to each scenario, or a run that refused. Not an emitter or a gate, for the same reason. `workflows:selftest` holds it. |
| `render-worktree-context.mjs` | helper | Probes and allocates a worktree's ports into `.worktree/ports.env`, and renders its briefing from `.claude/worktree-CONTEXT.md.tmpl`. It is the one reader of `ports.env`, which it reads in every sibling worktree to keep their ports apart; the calculator server is given `PORT` instead. It reads the template beside itself, so `new-worktree.sh` runs the new worktree's copy. |
| `run-tests.mjs` | test runner, `calculator:test`; selftest, `tests:selftest` | Runs Node's own test runner over the files its quoted patterns match and prints its usual report, and fails the run on a failing test, a pattern that matches no file, or a matched file that declares no test, which Node's runner reports as one passing test. It reads each matched file through `test-trace.mjs` and fails the run on metadata that reader refuses, and on a test that reader and the runner do not both see, keyed by its line and name: one made in a loop, by a helper or inside another test's body, or one under a condition. Imported by `check-thresholds.mjs`, it runs once with Node's own coverage and returns the runner's summary. `RUN_TESTS_ROOT` points it at a doctored copy. |
| `test-trace.mjs` | reader, used by `run-tests.mjs`; operator command, `cite`; selftest, `tests:trace:selftest` | The home of the convention every test's name and `// trace:` line follow: the IDs it proves, its role for each scenario, its layer and orchestration level, and a hash of each artifact it was written against. It reads a test file's source into its tests and the problems of their metadata, and hashes a scenario, an NFR requirement, a Binding Surface or a contract as its header defines; `cite <ref>` prints a ref with its current hash, to paste, and refuses a ref no trace line carries. It refuses no ID that is unknown and no hash that is stale, which `trace:check` refuses (`tools/trace/`), reading tests and specs through it. `TEST_TRACE_ROOT` points `cite` at a doctored copy. |
| `workflows.selftest.mjs` | selftest, `workflows:selftest` | Runs each workflow under `.claude/workflows/` against stubbed agents: `build-change-task.js` with the review sizes and red-first kinds in `tools/policy.json`, `review-prompts.js` with groups of findings it builds and the policy's `promptReview*` keys, and `verify-change-trace.js` with a change it builds and the policy's `verifyTrace*` keys, whose result it then renders with `render-trace.mjs` and `render-pr-body.mjs`. It refuses a workflow that stops, confirms, merges, holds or reports other than its header says, a prompt review that passes a finding below the threshold, merges an edit or a consolidation a majority of its skeptics did not uphold, or accepts a consolidation that does not say where each removed rule went, a trace that counts a group its tracer returned short or read at another commit, counts a gap nobody could verify as refuted, lets a skeptic's vote clear a proof that failed, or keeps a design reading a lens never gave, a renderer that writes with a scenario missing, a gap open or a row that did not pass, one that the Workflow runtime would not accept (a `meta` that is not a pure literal first, a phase `meta` does not declare, or a clock or random read), and a workflow file it has no suite for. `WORKFLOWS_ROOT` points it at a doctored copy. |
| `lib/trace.mjs` | helper | The scenario trace's one reading, shared by `render-trace.mjs` and `render-pr-body.mjs`: the workflow's result, the scenarios of a change's delta specs, the one-to-one match each refuses to write without, and the Markdown each writes. |
| `lib/bin-path.mjs` | helper | Resolves a `node_modules/.bin` executable by walking up, as the package manager does, so a gate that spawns a tool runs in a linked worktree. Never `npx`: a gate fails on a missing tool, it does not download one. |
