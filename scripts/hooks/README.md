# `scripts/hooks/`

**Claude Code hooks only: the in-session tier of the gate ladder, run on every matching tool call,
inside a budget of a few hundred milliseconds.** A git pre-commit or pre-push job is a script under
`scripts/`, never here. A hook may be unsound, because a slower tier never trusts it
(`CLAUDE.md` § The gate ladder); it may not be slow, and it never blocks a stop.

A file here runs only when `.claude/settings.json` registers it, and a running session picks up a
hook added to that file with no restart (`.claude/README.md` § The hooks). Where this table and the
settings file disagree, the settings file wins.
The settings file registers `CNT-HOOKS` hooks.
Every hook carries the same four-part header as a gate (`CLAUDE.md` § Standing rules for prompts and
gates), and every one can be run by hand with empty input, where it exits clean with nothing to do.
`check:prompts` holds the words of each file's string literals here, but a selftest's, to a budget in
`tools/policy/prompt-budgets.json`, since a refusal is text the blocked session acts on
(`docs/decisions.md` § D-59); a header is a comment, and keeps its incident.

| `_shared.mjs` | none: imported | | The helpers every hook here shares. The trunk's name, `TRUNK`, which the two Bash guards import, so it is named once. Some read: the repository root (`ROOT`), the stdin reader that returns null on empty input (`readHookInput`), and the payload and file readers (`editTarget`, `toRepoRel`, `header`, `readOr`). Some judge generated output (`hasGeneratedBanner`, `bannerCheckApplies`, `generatedFileRedirect`). `checkoutOf` finds the checkout a payload's `cwd` is in, and `editedCheckout` the checkout an edited file's own path is in, with the path relative to it; each runs git with no inherited `GIT_*` variable, which would point it elsewhere, through `gitEnv`, which `guard-git.mjs` imports for the same reason. `runTask` runs a task without a shell, through `mise run`, and refuses a task that checkout's own `tasks.toml` lacks, and a checkout with none; `taskLaunch` says what it would do. | `block-generated-edit.mjs` | `PreToolUse` on Write and Edit | yes | Refuses an edit to generated output, and names the hand-maintained source where the change belongs. | `gate-summary.mjs` | `Stop` and `SubagentStop` | never | Runs the fastest gates concurrently over the checkout the stopping agent worked in, with `citations:check` reading untracked files too, and prints one verdict line, which says what each gate read from that gate's own output. It never denies the stop: a hook people disable is a lie in version control. Its header gives the measured cost of each event. |
| `gate-summary.selftest.mjs` | none: `gate-summary:selftest` | | The Stop hook's tests, and the edit hook's placing of an edit. An untracked file with a broken pointer turns its verdict to FAIL for that reason, and an ignored one does not. Over scratch repositories, `checkoutOf` gates a linked worktree there and falls back otherwise, and a copy of the hook runs its gates in a linked worktree and says what that worktree's own gate read. `runTask` launches mise in a scratch checkout with a `tasks.toml`, and refuses a task that file lacks and a checkout whose tasks are a `package.json`'s scripts alone. A copy of `block-generated-edit.mjs` refuses an edit to each path the redirect table assigns, and to a bannered file, in a linked worktree with the reason it gives in the primary checkout, and with `GIT_DIR` in its environment, and passes a path in no checkout of the repository. A pre-push job and a CI step. |
| `guard-git.mjs` | `PreToolUse` on Bash | yes; its git rules in a linked worktree only, but for `git worktree prune` | Tokenises the command and refuses, from a worktree, a push, checkout, branch write or merge against a protected branch, and `git worktree`, `gc` and `prune`. It refuses every git command in a directory under `.claude/worktrees/<name>/` where git answers for another checkout, which is what a worktree removed under a session leaves. From any checkout, it refuses a `gh pr create` that does not name `main` as its base, a `gh pr review --approve`, in any spelling, since an approval is the person's gate on a head on the high-risk floor (`docs/decisions.md` § D-57), and a `gh pr merge --admin`, which merges past the checks the trunk's ruleset requires; from a worktree, any `gh pr merge` but auto-merge (`docs/decisions.md` § D-47). From any checkout, it refuses a `git worktree prune` that is not a dry run, which in a dev container takes every host worktree's record. Also from any checkout, it refuses graphify's `update`, `watch`, `hook install` and `claude install`, run by name or as a Python module, unless one asks for help, which erode the local code graph or write graphify's advice to run `update` into `CLAUDE.md` (`docs/decisions.md` § D-20). Where the command runs is the payload's `cwd`, never `CLAUDE_PROJECT_DIR`, which stays at the primary checkout after `EnterWorktree`, and it asks git there with no inherited `GIT_*` variable, which would point git at another checkout. Fails closed in a worktree when it cannot read its input. |
| `guard-unprovisioned-worktree.mjs` | `PreToolUse` on Bash | yes, in a linked worktree not on an `agent/*` branch | Refuses every command in a worktree `scripts/new-worktree.sh` did not provision, which `EnterWorktree`'s native fallback leaves on a `worktree-<name>` branch with no briefing; the branch name is the signal. Where the command runs is the payload's `cwd`, and it asks git there with no inherited `GIT_*` variable, as `guard-git.mjs` does. It is a file of its own, off the high-risk floor that holds `guard-git.mjs`, so a change to it alone needs no person (`docs/decisions.md` § D-58). |
| `guard-workflow-edit.mjs` | `PreToolUse` on Write and Edit | yes, on a workflow only | Refuses an edit that would leave a workflow other than `.github/workflows/pr-review.yml` able to approve a pull request itself or pass the `verify` check the trunk's ruleset requires: a grant of `pull-requests: write`, `statuses: write`, `checks: write` or `write-all`, or, outside `verify.yml`, a job named for that check. It judges the file as the edit would leave it, through `forgeProblems` in `scripts/pr-review.mjs`, and reads the check's name from `tools/policy/pr-review.json` (`docs/decisions.md` § D-57). Every other path passes before anything loads; on a workflow it fails closed when the result will not parse or the policy will not read. It sees Write and Edit alone, so a workflow written through Bash passes it. |
| `worktree-create.mjs` | `WorktreeCreate` | yes | Provisions through `scripts/new-worktree.sh`, so a worktree is always `agent/<name>` cut from `origin/main` with a rendered briefing, never Claude Code's native fallback. |
| `worktree-remove.mjs` | `WorktreeRemove` | no | Removes the checkout, keeps the branch, and runs the branch sweep for paths under `.claude/worktrees/` only. It prunes no record itself, and for any other path touches none. |
| `worktree-hooks.selftest.mjs` | none: `worktree:selftest` | | The negative tests for the two worktree hooks, the guard (run as Claude Code runs it in a worktree a session has entered), the unprovisioned-worktree guard, which must refuse a `worktree-*` worktree by its reason with no `cwd` in the payload and with an inherited `GIT_DIR`, where `guard-git.mjs` must now pass it, and the branch sweep, and the check that every command `.claude/settings.json` registers loads its script from any working directory. It also renders the briefing template through a scratch copy of `scripts/render-worktree-context.mjs`, with values holding `&` and `\`, and asserts that no placeholder survives, that nothing is written outside the worktree path given, and that `ports.env` names its reader and no file this checkout lacks. It runs a copy of `scripts/new-worktree.sh` from a scratch checkout that trails its remote by a template change, and asserts the briefing is the base's template, and the checkout's once the script is doctored back to the checkout's renderer. From a scratch checkout with this checkout's `.vale.ini` and `.gitignore`, it asserts a worktree gets the checkout's Vale styles and stays clean to `git status`. It also asserts that none reach the worktree once the copy is doctored out, and that a checkout with no styles still provisions and warns that Vale checks no prose. Where the base tracks a style named `Layout` under the StylesPath, which that `.gitignore` must track and no synced style beside it, the worktree gets both it, as the base has it, and the synced styles; doctored back to skipping the StylesPath whole, it gets no synced style; and with the tracked style alone, it warns. With `.git/config.lock` held, as a concurrent run holds it, the script must still provision and write no upstream; doctored back to one `git worktree add -b`, it fails on the lock and leaves its branch. A run that fails at an occupied path deletes the branch it made, and one whose branch already existed keeps that branch. The sweep keeps a clean, contained worktree with no process in it while HEAD there is younger than `worktreeGcMinAgeHours`, as an agent's is between its calls, with and without a commit beyond the trunk. One idle past it goes, and so does one named by `--finished`. A lane whose branch `--discard` names goes at once with the branch, though no proof contains it, and its tip is logged; a dirty one is kept by its reason. Against a fixture bare repository as the trunk's remote, `--remote` deletes a remote agent branch whose patches are upstream, logs it and prints its restore command, and `--dry-run` reports it and deletes nothing. Each by its reason, it keeps a remote branch with a commit not upstream, a protected one, one a kept worktree has checked out and one whose tip this repository never fetched; a human branch it passes unreported. An unreachable remote deletes nothing, says why, and the run does not fail. A stub `git` first on `PATH` reports a branch at a tip the remote has moved past, and the lease refuses its deletion by git's reason. A run given `--discard`, or `--finished`, deletes no remote branch even with `--remote`, and says why; `--discard` followed by nothing, and either flag followed by another flag, is refused by its reason and leaves the remote as it was. The control is a run without `--remote`, as the `WorktreeRemove` hook makes, which neither reads nor changes the remote. From a worktree, the guard refuses a `git worktree remove` typed there and lets that sweep run. It runs a push to `main` and a merge from the worktree, its subdirectory and the primary checkout with an inherited `GIT_DIR` naming the other checkout, and again with no `GIT_*` key as the control, and asserts the same verdict from each. It runs the guard's approval and merge rules from the primary checkout and a worktree, with a comment review and a request for changes as controls. It runs its worktree-prune rule from both, with a dry run as the control, and its graphify rule from both, with graphify's reading commands and the near misses of each refused command as controls. It runs the workflow-edit guard over Write and Edit payloads aimed at this checkout's workflows, which it never writes, with a routine step, the reviewer's own workflow and a path outside the workflows as controls, and against a doctored copy of `tools/policy/pr-review.json` with the required check renamed. It holds the sweep's containment after a rebase merge through a stub `gh` first on `PATH`, so no case reaches GitHub. In a scratch repository with a live worktree, a removed one and one whose parent directory is gone too, as a host worktree is to a dev container, a copy of the remove hook given a foreign path keeps every record. The sweep refuses `git worktree prune` by its reason and keeps the unseen record holding its branch; the control is the same repository once that parent is back, where both stale records are pruned. For an owned, locked worktree whose admin directory's name collided with another's, the hook's fallback removes its own record and keeps the other, and for one whose `.git` file is rewritten to name another's admin directory, it leaves that record alone. It reads the dev container's Dockerfile for `gc.worktreePruneExpire` set to `never`. Each case asserts the reason a refusal reports, not the refusal alone. A pre-push job. |
